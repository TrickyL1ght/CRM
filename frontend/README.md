# Фронтенд МясоПром CRM

Локальное приложение на HTML, CSS и JavaScript (ES modules). Требуется Node.js 22+. Установка зависимостей и сборка не нужны. Go-код и маршруты backend не изменены. Исходный `meatflow_crm.html` сохранён отдельно как макет.

## Запуск

В PowerShell из корня проекта:

```powershell
cd frontend
npm run dev
```

Откройте http://127.0.0.1:5173. Backend должен быть запущен отдельно на порту 8080, с подготовленной базой и миграциями. Фронтенд не запускает миграции и не меняет настройки базы.

Другой адрес API или порт интерфейса:

```powershell
$env:API_TARGET = 'http://127.0.0.1:8080'
$env:FRONTEND_PORT = '5173'
npm run dev
```

Node-сервер обслуживает статические файлы и проксирует `/api/supply`, `/api/supply/:id`, `/api/offal`, `/api/sales` на существующие маршруты Go без префикса `/api`. Прокси нужен для локальной разработки; это не изменение backend API. Сервер слушает только `127.0.0.1`.

## Что реализовано

- Реестр поставок, поиск по поставщику/номеру/виду сырья, фильтры вида и дат.
- Создание, редактирование и удаление поставок с подтверждением и обработкой ошибок.
- Выбор субпродуктов из серверного справочника.
- Показатели поступлений, продаж и остатков, вычисляемые по `/supply` и `/sales`.
- Просмотр продаж и справочника субпродуктов.
- Состояния загрузки, пустого списка и ошибок; адаптивная вёрстка и доступные модальные окна.

Данные не подменяются демонстрационными. Если API недоступен, показывается ошибка. При сбое загрузки продаж остатки отображаются как «—».

## Контракт текущего API и ограничения

Форма отправляет `livestockType`, `dateOfReceipt` (Unix seconds), `commingFrom` (именно такое написание в модели), `weight` (целые кг), `offals` и `sale`. При редактировании сохраняет загруженное поле `sale`. Стандартные виды: `cattle`, `pig`, `sheep`, `poultry`; можно ввести другой вид длиной до 25 символов. Даты поступления сохраняются как местный полдень выбранного дня.

Frontend использует актуальные Go-модели; Postman-коллекция и HTML-макет содержат поля, которых в этих моделях нет. Авторизация и ветконтроль пока не реализованы. Для продаж и справочника API предоставляет только чтение.

В текущем backend есть ограничения, которые фронтенд не исправляет:

- В `ListSupplies` используется `Preload("Sales")`, хотя поле модели называется `Sale`. Если сервер возвращает ошибку списка, интерфейс покажет её; для исправления требуется отдельное изменение API.
- Обновление связей субпродуктов зависит от поведения `Save` на backend: снятие отметки может не удалить существующую связь. После сохранения интерфейс заново загружает данные сервера.
- Удаление поставки со связанными продажами или субпродуктами может отклоняться внешними ключами базы. Ошибка будет показана в диалоге.

## Проверки

```powershell
npm run check
npm test
```

Тесты проверяют фильтрацию, остатки, формирование JSON, валидацию, экранирование и прокси на изолированном HTTP-сервере. Они не обращаются к рабочей базе и не изменяют реальные поставки.
